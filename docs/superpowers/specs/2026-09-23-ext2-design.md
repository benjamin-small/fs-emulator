# ext2: the second filesystem family

Design for slice 2 of the ext work: a `crates/ext` crate that formats,
mounts, and operates a minimal ext2 volume on the shared `fs-core` disk,
byte-accurate enough that `e2fsck` calls its images clean and Linux mounts
them, plus the wasm wrapper's generic support so the explorer can load one.
The ext3 journal is slice 3; the explorer's ext panels and lessons are
slice 4.

## Decisions (2026-09-23, with the user)

1. **On-disk shape: minimal ext2 revision 1 with 1 KiB blocks.** 128-byte
   inodes; feature flags `filetype` (incompat) and `sparse_super`
   (ro-compat) only; direct, single-indirect, and double-indirect blocks;
   no htree, extents, 64-bit, checksums, `resize_inode`, or extended
   attributes. 1 KiB blocks make the 16 MiB default disk two block groups,
   so a learner sees a backup superblock. Inode 8 stays reserved so slice 3
   adds `has_journal` without a relayout.
2. **Correctness gate: e2fsprogs in CI.** Tests write images to a temp
   directory and run `e2fsck -fn` (must be clean), `dumpe2fs` (fields must
   match the geometry), and `debugfs` (`ls -l` and `cat` must match the
   emulator; `stat` where its output is simple to compare). They skip with a printed notice on machines without the tools
   and fail instead when `CI` is set; the CI job installs `e2fsprogs`. A
   Linux loop-mount test stays behind `--ignored`, like the FAT mount test.
3. **The wasm wrapper gains generic ext support now:** `Inner::Ext`,
   `formatExt2`, `fromImage` detection by the ext magic, `fsType()` of
   `"ext2"`, and the `NotFat` / `NotExt` codes produced for real. No
   ext-specific DTOs until slice 4; one ext-only scalar method,
   `blockGroupCount(): number`, exists so `NotExt` has a real producer.
4. **Overwrite reuses blocks in place.** `write_file` keeps a file's
   existing blocks in order, frees the tail when the file shrinks, and
   allocates when it grows. That is what ext does, and it is a lesson of its
   own beside FAT's free-and-reallocate.
5. **Allocation is goal-based by group**, like ext2: a new inode goes in
   its parent directory's group when one is free there; a file's blocks come
   from the inode's own group first, then the following groups, wrapping
   around. Block groups are a behaviour, not only a layout.

## Outcome

- `ExtFs` implements `FileSystem`; every operation journals its bytes
  through the shared `OpRecord` machinery, so the timeline, diff, rewind,
  and terminal work on an ext volume with no UI change.
- A formatted default disk, and any sequence of the supported operations,
  produce an image that `e2fsck -fn` reports clean and that `debugfs`
  reads back identically to the emulator.
- The wasm `Volume` formats, loads, and detects ext2 images; the explorer
  refuses them with a clear status (`no adapter for ext2`) until slice 4.

## Non-goals

- The journal (slice 3); the ext panels, lessons, adapter, and terminal
  vocabulary (slice 4).
- htree directories, extents, 64-bit, checksums, `resize_inode`, extended
  attributes, symlinks, hard links, device nodes, `rename`, `truncate` as
  its own operation, sparse files (holes), block sizes other than 1 KiB.
- Users and permissions beyond fixed modes (`0644` files, `0755`
  directories, `0700` for `lost+found`), uid and gid 0.
- Matching `mke2fs` byte for byte.

## 1. Crate and core

`crates/ext` depends only on `fs-core`, zero external dependencies, no I/O,
clock, or threads; it builds for `wasm32-unknown-unknown`. Modules:

| module | owns |
|---|---|
| `superblock.rs` | `Superblock` decode/encode, `ExtFormatOptions`, validation |
| `group.rs` | group descriptors, `Geometry` (derived numbers), the per-group layout (bitmap, bitmap, table, data), backup placement under `sparse_super` |
| `bitmap.rs` | bit set/clear/find over a block, padding bits |
| `inode.rs` | `Inode` decode/encode, the 128-byte layout, modes, times |
| `blockmap.rs` | logical-to-physical mapping through direct, single, and double indirect blocks; allocation and freeing of a file's blocks |
| `dir.rs` | directory entries: `rec_len` splitting, merging, scanning, the `.` and `..` entries |
| `alloc.rs` | goal-based inode and block allocation over the bitmaps, keeping the superblock and descriptor counters in step |
| `events.rs` | `ExtEvent` |
| `fs.rs` | `ExtFs`: `format`, `from_image`, the `FileSystem` impl, `write_raw` with the corruption gate, `layout`, `annotate_sector`, the inherent inspection methods |
| `lib.rs` | re-exports |

Two additions to `fs-core`, both pure:

- `run_op` moves out of `FatFs` into a shared free function
  `fs_core::disk::run_op(disk: &mut Disk, history: &mut Vec<OpRecord>, op: String, body: impl FnOnce(&mut Disk) -> Result<()>) -> Result<OpRecord>`
  with the same contract: begin, run, end, roll every `before` back in
  reverse order on error without re-journaling, push on success. `FatFs`
  keeps its method as a thin wrapper, so its behaviour and tests are
  untouched; `ExtFs` uses the same function. (`FatFs::run_op`'s body takes
  `&mut Self`; the shared function takes `&mut Disk`, and the callers
  borrow what else they need before the call. If a `FatFs` body needs
  `self`, the wrapper keeps the old shape and delegates only the
  begin/rollback/push sequence. The plan settles which; behaviour is
  identical either way.)
- `DateTime::to_unix_seconds(&self) -> i64` and
  `DateTime::from_unix_seconds(i64) -> DateTime`, UTC, proleptic Gregorian,
  no clock, with tests at 1970-01-01, 1980-01-01, 2000-02-29, 2038-01-19.
  ext stores 32-bit seconds; the crate saturates at `u32::MAX` on encode.

Path rules stay as they are (`/` and `\` separators, no `.` or `..`).
ext names are case-sensitive and up to 255 bytes of UTF-8; the crate
rejects empty names, names longer than 255 bytes, and names containing
`/`, `\`, or NUL with `InvalidName`. The disk's sector size is the block
size (1,024 bytes), so "sector N" is block N in every region, annotation,
and UI label.

## 2. On-disk format

Little-endian throughout. Offsets are bytes from the start of the
structure.

**Superblock** (1,024 bytes at byte 1,024 of the disk, block 1):

| offset | field | value on the default disk |
|---|---|---|
| 0 | `s_inodes_count` u32 | `inodes_per_group * groups` = 1,024 |
| 4 | `s_blocks_count` u32 | 16,384 |
| 8 | `s_r_blocks_count` u32 | 0 |
| 12 | `s_free_blocks_count` u32 | kept in step: 16,234 after format |
| 16 | `s_free_inodes_count` u32 | kept in step: 1,013 after format |
| 20 | `s_first_data_block` u32 | 1 (1 KiB blocks) |
| 24 | `s_log_block_size` u32 | 0 |
| 28 | `s_log_frag_size` u32 | 0 |
| 32 | `s_blocks_per_group` u32 | 8,192 |
| 36 | `s_frags_per_group` u32 | 8,192 |
| 40 | `s_inodes_per_group` u32 | 512 |
| 44 | `s_mtime` u32 | 0 (never mounted) |
| 48 | `s_wtime` u32 | `now` at format and after every operation |
| 52 | `s_mnt_count` u16 | 0 |
| 54 | `s_max_mnt_count` i16 | -1 |
| 56 | `s_magic` u16 | 0xEF53 |
| 58 | `s_state` u16 | 1 (clean) |
| 60 | `s_errors` u16 | 1 (continue) |
| 62 | `s_minor_rev_level` u16 | 0 |
| 64 | `s_lastcheck` u32 | `now` at format |
| 68 | `s_checkinterval` u32 | 0 |
| 72 | `s_creator_os` u32 | 0 (Linux) |
| 76 | `s_rev_level` u32 | 1 |
| 80 | `s_def_resuid` u16, 82 `s_def_resgid` u16 | 0, 0 |
| 84 | `s_first_ino` u32 | 11 |
| 88 | `s_inode_size` u16 | 128 |
| 90 | `s_block_group_nr` u16 | the group this copy lives in |
| 92 | `s_feature_compat` u32 | 0 |
| 96 | `s_feature_incompat` u32 | 0x0002 (`FILETYPE`) |
| 100 | `s_feature_ro_compat` u32 | 0x0001 (`SPARSE_SUPER`) |
| 104 | `s_uuid` [u8; 16] | the options' UUID; default `e2f5ee00-2026-4923-8000-000000000001` |
| 120 | `s_volume_name` [u8; 16] | the label, NUL-padded; default empty |
| 136 | `s_last_mounted` [u8; 64] | zeros |
| 200 | `s_algo_bitmap` u32, 204 `s_prealloc_blocks` u8, 205 `s_prealloc_dir_blocks` u8 | 0 |
| 206..1024 | | zeros |

**Group descriptor** (32 bytes each, table in block 2 of group 0 and after
every backup superblock):

| offset | field |
|---|---|
| 0 | `bg_block_bitmap` u32 |
| 4 | `bg_inode_bitmap` u32 |
| 8 | `bg_inode_table` u32 |
| 12 | `bg_free_blocks_count` u16 |
| 14 | `bg_free_inodes_count` u16 |
| 16 | `bg_used_dirs_count` u16 |
| 18 | `bg_pad` u16, 20..32 reserved | zeros |

**Inode** (128 bytes; inode `n` is entry `(n - 1) % inodes_per_group` of
the table of group `(n - 1) / inodes_per_group`):

| offset | field |
|---|---|
| 0 | `i_mode` u16: `0x81A4` file (0100644), `0x41ED` directory (040755), `0x41C0` for `lost+found` (040700) |
| 2 | `i_uid` u16 = 0 |
| 4 | `i_size` u32 |
| 8 | `i_atime`, 12 `i_ctime`, 16 `i_mtime`, 20 `i_dtime` u32 |
| 24 | `i_gid` u16 = 0 |
| 26 | `i_links_count` u16 |
| 28 | `i_blocks` u32: 512-byte units, counting data and indirect blocks (`blocks * 2`) |
| 32 | `i_flags` u32 = 0 |
| 36 | `i_osd1` u32 = 0 |
| 40 | `i_block[15]` u32: 12 direct, then single-indirect, double-indirect, triple-indirect (unused, 0) |
| 100 | `i_generation` u32 = 0 |
| 104 | `i_file_acl` u32 = 0 |
| 108 | `i_dir_acl` u32 = 0 |
| 112 | `i_faddr` u32 = 0 |
| 116..128 | `osd2` zeros |

**Directory entry** (`filetype` feature): `inode` u32, `rec_len` u16,
`name_len` u8, `file_type` u8 (1 file, 2 directory), then the name.
`rec_len` is a multiple of 4, at least `8 + name_len` rounded up to 4, and
an entry with `inode == 0` is unused space. Entries never cross a block;
the last entry of a block runs to the block's end.

**Bitmaps:** one block each. Bit `i` of a group's block bitmap is block
`first_block_of_group + i`; bits past the group's last block (only the last
group is short) are set. Bit `i` of the inode bitmap is inode
`group * inodes_per_group + i + 1`; bits past `inodes_per_group` are set.

## 3. Format and geometry

`ExtFormatOptions { total_blocks: u32 (default 16,384), inodes_per_group: Option<u32> (None: derived), label: [u8; 16], uuid: [u8; 16] }`
with `Default`. Validation (`InvalidGeometry`): `total_blocks` at least 64
and at most 262,144 (the 256 MiB wasm cap), and not a count whose last
group is too short for its own metadata (for example 8,194 to 8,261; mke2fs
trims such a group instead, which this crate does not); `inodes_per_group` a multiple
of 8, at most 8,192, and at least 16; the derived default is
`clamp(round_up(total_blocks * 1024 / 16_384 / groups, 8), 16, 8_192)`,
the mke2fs ratio of one inode per 16 KiB.

`Geometry` (derived, cached on `ExtFs`, re-derived by `from_image` and by
the corruption gate): `block_size = 1024`, `first_data_block = 1`,
`blocks_per_group = 8192`, `groups = ceil((total_blocks - 1) / 8192)`,
`inodes_per_group`, `inode_table_blocks = inodes_per_group * 128 / 1024`,
`inodes_count`, and per group: `first_block`, `block_count`
(8,192 or the remainder), `has_superblock` (groups 0, 1, and powers of 3,
5, and 7), `superblock_block`, `descriptors_block`, `descriptor_blocks`
(`ceil(groups * 32 / 1024)`, 1 for up to 32 groups), `block_bitmap`,
`inode_bitmap`, `inode_table`, `first_data`.

Group layout, in blocks from the group's first block: the backup superblock
and descriptor table when `has_superblock`, then the block bitmap, the
inode bitmap, the inode table, then data. On the default disk: group 0 is
blocks 1 (superblock), 2 (descriptors), 3, 4 (bitmaps), 5..68 (inode
table), 69..8192 (data); group 1 is 8193 (backup superblock with
`s_block_group_nr = 1`), 8194 (descriptors), 8195, 8196, 8197..8260,
8261..16383. Block 0 is the boot block and is never written.

`format` writes, outside any operation so history starts empty: every
superblock copy, every descriptor table, both bitmaps of every group with
their metadata blocks and padding bits set, zeroed inode tables, inodes 1
to 10 marked used, the root directory (inode 2, mode 040755, one data block
with `.` and `..` both pointing at 2 followed by the `lost+found` entry, links 3), and `lost+found` (inode 11,
mode 040700, 12 data blocks, the first holding `.` (11) and `..` (2) and
the rest holding one unused entry spanning the block, links 2). Group 0's
`bg_used_dirs_count` is 2. The counters after format on the default disk:
free blocks 16,234 (group 0: 8,111; group 1: 8,123), free inodes 1,013
(group 0: 501; group 1: 512). `e2fsck -fn` is clean on this image; without
`lost+found` it is not.

`from_image(bytes)`: needs at least 2,048 bytes; reads the superblock at
1,024; `CorruptImage` when the magic is not 0xEF53 or the descriptors or
geometry do not fit the image; `Unsupported` when `s_rev_level != 1`,
`s_log_block_size != 0`, `s_inode_size != 128`, `s_feature_incompat` is not
exactly `FILETYPE`, `s_feature_ro_compat` is not exactly `SPARSE_SUPER`, or
`s_feature_compat` is not 0 (message names the feature: a volume without
`filetype` stores `name_len` as 16 bits, one without `sparse_super` puts
backups in every group, and `resize_inode` reserves descriptor blocks, so
the layout this crate derives would be wrong for any of them). The disk is the image truncated
to `s_blocks_count * 1024` bytes, as FAT truncates trailing bytes.

## 4. Operations

Every path operation passes the corruption gate first (section 6), then
resolves the path component by component from inode 2 with exact name
matching. All run inside one `run_op`; on error every byte is rolled back.

- **`create_file(path, data)`**: `AlreadyExists` if the name exists;
  `NotADirectory` if a component is a file; `FileTooLarge` if `data.len()`
  exceeds `u32::MAX` or the double-indirect capacity
  (`(12 + 256 + 65,536) * 1024` bytes); `DiskFull` when no inode or not
  enough blocks are free (`fs_core::Error::DiskFull` carries no message; the
  events and the unchanged bytes tell which). Allocates the inode in
  the parent's group when one is free there, else in the following groups
  in order, wrapping (section 5); writes the inode (mode 0100644, links 1, times `now`,
  `i_size`, `i_blocks`); allocates data blocks goal-based (section 5) and
  the indirect blocks as the mapping needs them; writes the data; inserts
  the directory entry (section 4, directories); updates the bitmaps, the
  descriptors, the superblock counters and `s_wtime`, and the parent's
  `mtime`/`ctime`. Empty data allocates no blocks.
- **`write_file(path, data)`**: `NotFound` if absent, `IsADirectory` for a
  directory. Reuses the file's existing blocks in logical order, frees the
  tail (data and indirect blocks no longer needed) when the file shrinks,
  allocates when it grows; writes the whole new content (the byte journal
  records only the bytes that changed, so the diff still shows exactly what
  moved). Updates `i_size`, `i_blocks`, `mtime`, `ctime`.
- **`read_file(path)`**: the bytes through the mapping; `IsADirectory` for
  a directory. `read_file`, `write_file`, and `delete_file` return
  `Unsupported` for an inode that is neither a regular file nor a directory
  (a symbolic link or device node in a foreign image stores other things in
  `i_block`), and `write_file`/`delete_file` return `CorruptImage` for an
  inode whose mapping is shorter than its size claims; `list_dir` and `stat`
  still list such inodes as files.
- **`delete_file(path)`**: `IsADirectory` for a directory. Removes the
  directory entry, frees the data and indirect blocks and the inode (bitmap
  bits and counters), sets `i_dtime` to `now`, `i_links_count` to 0, and
  leaves the rest of the inode and the data bytes in place (remnants, as on
  a real disk).
- **`create_dir(path)`**: `AlreadyExists`, `NotADirectory`, `DiskFull` as
  above. Allocates the inode (goal: the parent's group) and one data block
  holding `.` and `..`; mode 040755, links 2; bumps the parent's
  `i_links_count` and the group's `bg_used_dirs_count`.
- **`remove_dir(path)`**: `NotADirectory` for a file; `DirectoryNotEmpty`
  when any entry other than `.` and `..` has a non-zero inode; refuses `/`
  with `InvalidPath`. Frees the block(s) and inode, decrements the parent's
  links and the group's `bg_used_dirs_count`.
- **`list_dir(path)`**: entries in on-disk order, excluding `.` and `..`,
  each with `EntryInfo { name, is_dir, size, created: None (ext2 has no
  birth time; `ctime` is a change time), modified: mtime, accessed: atime }`.
- **`stat(path)`**: the same `EntryInfo`; `/` is a directory of size
  `i_size`.
- **`set_now(DateTime)`**: the clock for every timestamp written afterwards.

**Directories.** Insert: scan the directory's blocks for the first entry
whose slack (`rec_len - actual_len`, or the whole `rec_len` when
`inode == 0`) fits the new entry; split it. When no block has room,
allocate a new block (goal-based) holding the entry with `rec_len` spanning
the block, and extend the directory's `i_size` and `i_blocks`. Remove: set
the entry's `inode` to 0 when it is the first in its block, else add its
`rec_len` to its predecessor's, the kernel's rule; a directory's blocks are
never freed by a removal. `.` is the first entry of the first block and
`..` the second.

**Timestamps.** `now` starts at `DateTime::default()` (1980-01-01, so
tests are deterministic) and every written time is
`now.to_unix_seconds()`: `atime`, `ctime`, `mtime` at create; `mtime`,
`ctime` on write and on the parent at insert and remove; `dtime` at delete;
`s_wtime` after every operation.

## 5. Allocation

Inodes: the goal group is the parent directory's group; scan its inode
bitmap from `s_first_ino - 1` for group 0 and from 0 otherwise; when the
goal group has none, scan the following groups in order, wrapping. Blocks:
the goal group is the inode's group; scan its block bitmap from the first
data block of the group; when short, continue with the following groups,
wrapping; a request for `n` blocks may straddle groups. Every allocation
and free updates the group's bitmap, the descriptor's free count, and the
superblock's free count in the same operation. A request that cannot be
met fails with `DiskFull` before any byte is written (the counts are
checked first), so `run_op` has nothing to roll back in that case; the one
exception is a parent directory that turns out to need a new block for the
entry, which is discovered inside the operation and rolled back. The cached
superblock and descriptors are restored alongside the disk whenever an
operation fails after they changed.

Indirect blocks are allocated with the same goal, after the data blocks
they point at (the data is allocated first, then the pointer blocks the
mapping needs); `i_blocks` counts them. Freeing walks the mapping and
returns every data and indirect block, zeroing nothing (remnants).

## 6. Raw writes and the corruption gate

`write_raw` journals like FAT's. When the written range touches the primary
superblock (block 1) or the primary descriptor table (block 2 on the
default disk; in general `descriptors_block` and its `descriptor_blocks`),
the crate re-parses both. A parse that succeeds and fits the physical disk
is adopted (geometry and counters follow the bytes, the disk is the truth);
one that fails sets `corrupt: Option<Error>`, every path method then fails
with `CorruptImage("superblock or group descriptors no longer parse after a raw write: {cause}")`
until a later raw write repairs them, and `corruption()` (the trait method)
reports it. `layout`, `annotate_sector`, `disk`, `history`, and `write_raw`
keep working from the last good geometry. Backup copies are not consulted
(a lesson for slice 4: repair from the backup by hand with `dd`).

## 7. What the explorer sees

**Regions** (`layout()`), reusing the existing kinds with descriptive
names, per group in disk order:

| name | kind | blocks |
|---|---|---|
| `boot block` | `Boot` | 0 |
| `superblock` / `backup superblock (group N)` | `Boot` | the superblock block |
| `group descriptors (group N)` | `Metadata` | the descriptor block(s) |
| `block bitmap (group N)` | `AllocationTable` | one block |
| `inode bitmap (group N)` | `AllocationTable` | one block |
| `inode table (group N)` | `Metadata` | `inode_table_blocks` |
| `data (group N)` | `Data` | the rest of the group |

**Annotations** (`annotate_sector(block)`), each with a byte range within
the block, a label, and a value:
- superblock copies: every field in the table of section 2, values in
  decimal except magic, feature flags, and the UUID in hex, the label as
  text;
- descriptor tables: per descriptor, the five counted fields, labelled with
  the group number;
- bitmaps: runs of used and free bits as `blocks 69..80: used` /
  `inodes 12..512: free`, plus `padding` for the bits past the end;
- inode table blocks: per inode slot, `inode N` with mode (octal and a
  word: file, directory, free), size, links, blocks, the first direct
  pointers, and the times as dates, or `free` when the mode is 0;
- directory blocks (known through `block_owners()`): per entry, inode,
  `rec_len`, `name_len`, file type, name, or `unused` for a zero inode;
- indirect blocks: `pointer[i]` runs, e.g. `blocks 0..255: 4096..4351`;
- data blocks: no annotations.

**Events** (`ExtEvent`, each with an absolute byte range and a
plain-language `Display`): `InodeAllocated { inode, group }`,
`InodeFreed { inode }`, `BlocksAllocated { first, count, group }`,
`BlocksFreed { first, count }`, `InodeWritten { inode, path }`,
`DirEntryWritten { dir_inode, name, block }`,
`DirEntryRemoved { dir_inode, name }`, `DataWritten { inode, bytes, block }`
(one per contiguous run), `IndirectWritten { inode, level, block }`,
`BitmapUpdated { group, which: Blocks | Inodes }`,
`CountersUpdated { free_blocks, free_inodes }` (superblock and descriptor
together), `RawWrite` from core. Kinds are the snake_case names.

**Inspection**, inherent on `ExtFs` for tests and slice 4:
`superblock() -> &Superblock`, `geometry() -> &Geometry`,
`group_descriptors() -> &[GroupDescriptor]`, `inode(n) -> Result<Inode>`,
`lookup(path) -> Result<u32>`, `dir_entries(path) -> Result<Vec<(u32, usize, DirEntry)>>`
(block, offset within it, entry; in disk order, unused entries included),
`block_owners() -> BTreeMap<u32, BlockOwner { inode, path, role: Data | Directory | Indirect }>`
(a walk from the root; used by `annotate_sector` to tell directory and
indirect blocks from data), `corruption() -> Option<&Error>` (also the
trait method).

## 8. Wasm

- `enum Inner { Fat(FatFs), Ext(ExtFs) }`; `fs()`/`fs_mut()` match both;
  `fat()` returns `Err(NotFat)` on an ext volume and a new `ext()` returns
  `Err(NotExt)` on a FAT one; both codes join the README's list and the
  uniqueness test.
- `static formatExt2(options?: ExtFormatOptions): Volume` with the DTO
  `ExtFormatOptions { totalBlocks?: number; inodesPerGroup?: number; label?: string; uuid?: string }`
  (`uuid` as 32 hex digits, optionally hyphenated; the label at most 16
  bytes; unknown keys rejected like FAT's; the 256 MiB cap enforced).
- `detect` gains `Detected::Ext` when `len >= 1082` and the u16 at 1080
  is 0xEF53, checked before the FAT signature; `from_image` maps
  `Ext => ExtFs::from_image`, `Fat => FatFs::from_image`, and `Unknown` to
  `Unsupported("no recognisable filesystem signature")` (today's
  "image is shorter than one sector" and "signature is not 55 AA" texts
  survive for short and unsigned images through the FAT arm only when
  `detect` says `Fat`; the boundary test in `tests/volume.rs` that asserts
  `CorruptImage` on a 100-byte image changes to expect `Unsupported`, and
  the README's Detection paragraph is rewritten).
- `fsType()` returns `"ext2"`; `layout`, `annotateSector`, history, sector,
  raw, and image methods work unchanged. `blockGroupCount(): number` is the
  one ext-only method this slice adds (throws `NotExt` on a FAT volume).
- `crates/wasm/README.md`: `formatExt2`, the DTO, detection order, the two
  codes. `web/demo` is untouched. The explorer's `familyIdOf("ext2")`
  throws `no adapter for ext2`, which `load()` turns into a status; that is
  the intended behaviour until slice 4.

## 9. Tests

- Unit tests in every module: encode/decode round trips for the
  superblock, descriptor, inode, and directory entry; bitmap find/set/clear
  and padding; the geometry table of section 3 for the default disk and for
  a 64-block and a 262,144-block disk (backup groups 0, 1, 3, 5, 7, 9, 25,
  27); `rec_len` split and merge (covered through the directory integration tests
  in `tests/ext2.rs`); mapping arithmetic at the 12-, 268-, and
  65,804-block boundaries.
- `crates/ext/tests/ext2.rs`, through the public API and as a
  `Box<dyn FileSystem>`: format counters and layout; create, list, stat,
  read, write (grow within direct, into single, into double; shrink back),
  delete (remnants stay; dtime set; counters), directories (create, nest,
  remove, not-empty, growth past one block with 60 names), name validation,
  the goal-group rule (a file created under `/dir` in group 1 gets group 1
  inodes and blocks), `DiskFull` at exhaustion with nothing written, every
  operation rewinding byte for byte through history, `from_image` round
  trip and each `Unsupported` reason, the corruption gate (zero block 1:
  path ops fail, `corruption()` set, `layout()` works; restore: clears).
- `crates/ext/tests/e2fsprogs.rs`: a helper finds `e2fsck`, `dumpe2fs`,
  `debugfs` on `PATH` and under `/opt/homebrew/opt/e2fsprogs/sbin`; when
  missing, prints `e2fsprogs not found; skipping` and returns, unless `CI`
  is set, in which case the test fails. Cases: the default format is
  clean (`e2fsck -fn` exits 0 and prints no fix lines); `dumpe2fs -h`
  reports the block count, inode count, free counts, blocks and inodes per
  group, inode size, features, and label; after a scripted sequence (a
  100-byte file, a 20 KiB file, a 300 KiB file, a directory with 60 entries,
  an overwrite that shrinks, a delete, a remove_dir) `e2fsck -fn` is still
  clean and `debugfs -R "ls -l /"` and `debugfs -R "cat /big.bin"` match the
  emulator's `list_dir` and `read_file`.
- `crates/ext/tests/mount_linux.rs`, `#[ignore]`, `cfg(target_os = "linux")`:
  `losetup`/`mount -t ext2 -o loop` the image read-only, read two files,
  unmount.
- `crates/wasm/tests/volume.rs`: `formatExt2` basic info and `fsType`,
  detection order, `NotFat` on an ext volume and `NotExt` on a FAT one, the
  `Unsupported` code for an unsigned image, a create/read round trip and
  `layout()` names on ext.
- CI: the check job adds `sudo apt-get install -y e2fsprogs` before
  `cargo test --workspace` (it is present on the runner image already; the
  install is the documented guarantee), and `CI=true` is set by GitHub,
  which makes the e2fsprogs tests a hard gate there.

## 10. Rulings

- The disk sector size is the block size. The UI's dump and ribbon label
  by sector, so an ext volume reads "sector 5 · inode table (group 0)";
  slice 4 decides whether to say "block".
- Existing `RegionKind`s are reused with descriptive names; slice 4 adds
  kinds if its panels need them, and the TS union then changes with them.
- `write_file` writes the whole new content, not a minimal diff; the byte
  journal already records only what changed.
- `i_size` is 32-bit; `i_dir_acl` is not used as a size extension.
- `s_wtime` and the counters change on every operation, so the superblock
  is part of every operation's diff, which is true to ext and shows in the
  ribbon; slice 3's journal makes that the point.
