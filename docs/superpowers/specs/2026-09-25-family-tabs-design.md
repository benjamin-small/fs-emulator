# fs explorer: one tab per filesystem family, and the Step strip's replacement

Status: approved 2026-09-25. Binding for the tabs work; `docs/superpowers/specs/2026-09-24-ext-explorer-design.md` and `2026-09-23-fs-adapter-design.md` stay binding for the adapter seam and the ext panels except where this spec amends them (section 7).

## 1. Why

The explorer grew from a FAT16 tool into a two-family tool by swapping panels in place: one page, one `Volume`, and the family flips underneath the learner from four unrelated places (the Filesystem select in the Actions panel's Format details, Load image, the terminal's `mkfs --type`, and starting a lesson of the other family). Every flip clears the timeline, the FAT map becomes Block groups, a Journal panel appears or vanishes, the lesson picker mixes twelve lessons in two `<optgroup>`s, and `mkfs`'s help describes both families at once. The Step strip under the top bar tries to be a status line, a navigator (up to 18 `Block N` buttons), and a narrative (an ext3 create emits about 30 events) in one wrapping 210 px box, while the Timeline footer duplicates the navigator.

Decisions made with the user on 2026-09-25:

1. Top-bar tabs `FAT16 | ext` switch the whole workspace. No home page. FAT16 stays the default tab and disk.
2. Each tab keeps its own workspace: its own volume, timeline, selection, dump position, panels' local state, running lesson, and terminal working directory. Switching loses nothing; two disks in memory is fine.
3. One ext tab, ext3 by default; the ext Format form's Variant select still offers ext2.
4. The Step strip and the Timeline footer become a one-line Operation bar (timeline controls plus summary) and a What changed panel at the top of the right column (changed blocks as ranges, events grouped into phases).

Outcome: two distinct workflows on one page. Inside a tab nothing can change the family: the Format details format the tab's family, the picker lists the tab's lessons, `mkfs` knows the tab's types, and an image of the other family opens in its own tab. Every FAT string, lesson string, and colour stays identical below the components; `crates/` is untouched.

## 2. State: one `Workspace` per family, explicit context, both kept mounted

A forwarding façade (`volume` forwarding to the active workspace) is rejected: Svelte compiles `$state` class fields to private signals, so a Proxy must forward private-field access and bind methods or throw; the store-internal deriveds (`layers.chain` reading `volume.epoch` and `selection.path`) must be bound to one workspace, so injection is needed anyway; and one shared component tree leaks component-local state across tabs (`HexView.scrollTop`/`lastNonce`, `Timeline.playing`, `TreeNodeView.open`, `StringsPanel` scope, the Format forms' fields, `JournalPanel`'s phase select, `BlockGroupMap`'s scroll, `ActionsPanel` path/content). With explicit context each tab has its own component instances, and deleting the singleton exports makes any missed import site fail svelte-check.

**`src/state/workspace.svelte.ts`** (new):
- `class Workspace { readonly id: FsFamilyId; readonly vfs = new Vfs(); readonly selection: SelectionStore; readonly volume: VolumeStore; readonly layers: LayersStore; readonly scenarios: ScenarioRunner; get active(): boolean; goToStep(step: number): void }`. The constructor assigns the four stores explicitly in dependency order (`selection = new SelectionStore(() => this.volume.clearMessages())`, `volume = new VolumeStore(id, selection, () => { this.vfs.cwd = MOUNT; })`, `layers = new LayersStore(volume, selection)`, `scenarios = new ScenarioRunner(volume, selection)`); no TS parameter properties. `goToStep` replaces `src/state/navigate.svelte.ts` (`focusHistoryStep`), which is deleted.
- `class WorkspaceRegistry { activeId = $state<FsFamilyId>; opened = $state.raw<Workspace[]>([]); get active(): Workspace; activate(id): Workspace; loadImage(bytes: Uint8Array, fileName: string, from: Workspace): void }`. `activate` creates a workspace lazily (pushes to `opened` before setting `activeId`, never inside a getter or `$derived`). The ext workspace is created on first activation only (a tab click, `#ext` at load, or a routed Load image), so page load keeps today's cost; each workspace is about 33 MB (16 MB image in wasm memory, a 16 MB JS copy, the zero map) and is never disposed.
- `export const workspaces = new WorkspaceRegistry(parseRoute(location.hash, FAMILY_IDS) ?? DEFAULT_FAMILY)` and `export const [getWorkspace, setWorkspace] = createContext<Workspace>()` (Svelte 5.57).
- `loadImage(bytes, fileName, from)`: `Volume.fromImage(bytes)` and `familyIdOf(vol.fsType())`; on a throw, `from.volume.report(e)` (today's error on the current tab). Else `activate(id)`, `t.volume.mount(vol)`, and when `t !== from`, `t.volume.notice = "Opened ${fileName} in the ${FAMILIES[id].name} tab: it is an ${vol.fsType()} image. The ${FAMILIES[from.id].name} tab is as you left it."` (`a`/`an` by the type's first letter). A lesson running in the target tab is closed (its disk is gone), as a same-tab load does today.
  *Corrected during implementation: a same-tab Load image does not close a running lesson today; only a routed load (`t !== from`) closes the one running in the target tab. On a routed load the keyboard moves to the target tab's Load image input (`load-image-{id}`), since the input it was on is now hidden.*

**Store changes (`src/state/`):**
- `volume.svelte.ts`: constructor `(family: FsFamilyId, selection: SelectionStore, onAdopt: () => void)`, field `readonly family`; fields declared uninitialised and `adopt(FAMILIES[family].format())` in the constructor; `adopt` throws when `familyIdOf(vol.fsType()) !== family` and calls `onAdopt()`; `format(family = this.family, options?)` keeps its signature and rejects another family; new `mount(vol)` (adopt, clear messages, `selection.reset()`), `load(bytes)` becomes `mount(Volume.fromImage(bytes))`; `fail` becomes public `report`; new `notice = $state<string | null>(null)` and `clearMessages()` (status and notice), called by `run`, `seek`, `format`, `mount`. The `volume` export and the `DEFAULT_FAMILY` import go.
- `selection.svelte.ts`: constructor `(clearMessages: () => void)`; `select` calls it. The export goes.
- `layers.svelte.ts`: constructor `(volume, selection)`; the deriveds read `this.volume`/`this.selection`; new `hover = $state.raw<Interval | null>(null)` (section 6). The export goes.
- `scenarios.svelte.ts`: constructor `(volume, selection)`; `start(s)` throws `Error("lesson ${s.id} is for ${s.family}; this tab is ${volume.family}")` when they differ (the picker makes this unreachable; `Scenario.family` stays as the tab key). The export goes.
- `src/fs/index.ts`: `export const FAMILY_IDS = Object.keys(FAMILIES) as FsFamilyId[]`; `DEFAULT_FAMILY` re-documented as "the tab opened when the URL hash names none" and `FAMILIES` as "in the order of the top bar's tabs".

**New pure modules (node-tested):**
- `src/core/route.ts`: `parseRoute<T extends string>(hash: string, known: readonly T[], aliases: Readonly<Record<string, T>> = {}): T | null` (strips `#` and one leading or trailing `/`, lower-cases, looks the name up in `aliases` then `known`, else null) and `formatRoute(id: string): string` (`#${id}`). The app passes `{ fat: "fat16", ext2: "ext", ext3: "ext" }`.
- `src/core/keepScroll.ts`: `createScrollKeeper(el: { scrollTop: number; addEventListener; removeEventListener }, shown: boolean, raf = requestAnimationFrame)` records `scrollTop` on scroll only while shown and restores it in a `raf` callback on hidden to shown; `keepScroll: Action<HTMLElement, boolean>` wraps it. `display: none` zeroes a scroll box, so the dump and the block-group map use it.
- `src/core/observeWidth.ts`: ignore 0-width reports, so a hidden map keeps its last width instead of repainting at 1 px.

## 3. The page: tab bar, one `WorkspaceView` per opened tab

- **`src/components/TabBar.svelte`** (new), in the top bar right after the `h1` and before the Terminal button, no row of its own: `<div class="tabbar" role="tablist" aria-label="Filesystem">` with one `<button role="tab" id="tab-{id}" aria-selected aria-controls="workspace-{id}" tabindex={active ? 0 : -1}>` per `FAMILY_IDS`, labelled `FAMILIES[id].name` (`FAT16`, `ext`), plus a `lesson` badge (`<span class="tab-badge">lesson<span class="sr-only"> running</span></span>`) whenever that workspace's `scenarios.current` is set, on the active tab too so widths don't jump. Keyboard per WAI-ARIA tabs with automatic activation: Left/Right wrap, Home/End, roving tabindex, focus stays on the tab. No dirty marker and no mounted type in the label.
- **`src/components/WorkspaceView.svelte`** (new, prop `ws`): calls `setWorkspace(ws)`, then holds what `App.svelte` holds today below the top bar, reshaped by section 6: the `OperationBar`, the `Ribbon`, and the `.grid` (left: `DirTree`, `PANELS[ws.id].map`, `ActionsPanel`; center: `HexView`; right: `WhatChangedPanel`, `PANELS[ws.id].aside`, `StringsPanel`, `Inspector`). No footer. **`src/components/WorkspaceScope.svelte`** (new, `ws` + `children`): `setWorkspace(ws)` and renders the children, no DOM.

URL: a `$effect` calls `history.replaceState(null, "", formatRoute(activeId))` when the hash differs; `<svelte:window onhashchange>` activates `parseRoute(location.hash, …) ?? activeId` for pasted links. A bare URL stays FAT16.
- **`src/app.css`**: `.app { grid-template-rows: auto auto auto minmax(0, 1fr); }` (top bar, operation bar, ribbon, grid; the footer row and the `.step`/`.timeline` rules go); `.workspace:not([hidden]) { display: contents; }` (an author `display` would override the UA's `[hidden]` rule); the tab styles:

- **Duplicate ids** inside the workspace subtree become per tab: `action-path-{id}`, `opbar-heading-{id}`; `LessonPanel`'s grid measurement queries `.workspace:not([hidden]) .grid`.
- **Components that only swap their import line** to `const { volume, selection, layers, scenarios } = getWorkspace();` (bodies unchanged): `DirTree`, `TreeNodeView`, `Inspector`, `Ribbon`, `StringsPanel`, `StatusLine`, `LessonPanel`, `fs/fat16/FatMap`, `fs/fat16/FormatForm`, `fs/ext/ExtFormatForm`, `fs/ext/BlockGroupMap`, `fs/ext/JournalPanel`. ## 4. What each tab contains and what it drops

- **FAT16 tab:** left `Files`, `FAT map`, `Actions`; right `What changed`, `Strings`, `Inspector`. **ext tab:** left `Files`, `Block groups`, `Actions`; right `What changed`, `Journal`, `Strings`, `Inspector`. The Journal moves from under the map (its controls pushed Actions below the fold in the 220 px column) to the 340 px right column. `src/fs/panels.ts` renames `extras` to `aside` (`fat16: []`, `ext: [JournalPanel]`). The right column scrolls (`.col { overflow: auto }`), with `Inspector` taking the slack.
- **A first impression per tab:** the adapter seam gains `summary(): string` (`src/fs/adapter.ts`, implemented in `fs/fat16/adapter.ts` and `fs/ext/adapter.ts` from the mounted geometry): `FAT16 · 16 MB · 512-byte sectors · 2 KiB clusters`; `ext3 · 16 MB · 16,384 1 KiB blocks in 2 groups · 1,024-block journal, ordered mode`; `ext2 · 16 MB · 16,384 1 KiB blocks in 2 groups · no journal`. It is the Operation bar's empty state. Entering the ext tab for the first time shows a fresh ext3 disk: the amber journal band in the ribbon, Block groups on the left, the Journal panel on the right in ordered mode, the picker on the ext fundamentals.
- **Format details (`ActionsPanel.svelte`):** the Filesystem `<select id="format-family">`, the `family` state, and its `$effect` go; the form is `PANELS[volume.family].format`; the summary reads `Format (FAT16)` / `Format (ext2 / ext3)` from `FAMILIES[id].fsTypes.join(" / ")`. Load image stays under Format with a muted hint `FAT16 and ext images each open in their own tab.` and calls `workspaces.loadImage(bytes, file.name, ws)`.
- **Lesson picker (`ScenarioPanel.svelte`):** no `<optgroup>`; options are `lessonsFor(ws.id)`; the selection is kept per tab (`Record<FsFamilyId, string>` seeded with `defaultLessonFor(id).id`); the label stays `Learning scenarios`. `src/scenarios/index.ts` replaces `scenarioGroups`/`ScenarioGroup` with `lessonsFor(family, list = all): Scenario[]` and `defaultLessonFor(family): Scenario` (the first); `all` keeps its order. `extFundamentals.title` becomes `The fundamentals`.
- **Terminal (`src/shell/mkfs.ts`, `src/shell/storeHost.svelte.ts`, `TerminalPanel.svelte`):** `mkfsCommand` builds its spec from the tab's family only (`const own = { [host.adapter.id]: FAMILIES[host.adapter.id] }` into `mkfsTypes`/`mkfsFlagsFor`): summaries `Format /dev/hda (clears the timeline); --type picks fat16` and `Format /dev/hda (clears the timeline); --type picks ext2 or ext3`; `--label` is no longer merged; another family's type throws `ShellError("'ext3' is an ext type: switch to the ext tab to format one", { help: "types: fat16" })` (and the mirror on ext: `"'fat16' is a FAT16 type: switch to the FAT16 tab to format one"` with `help: "types: ext2, ext3"`); unknown types keep `unknown type 'ntfs'`. `createStoreHost(ws, closeTerminal, applyPrompt)` reads `ws.volume`/`ws.selection`. One xterm for the page: `TerminalPanel` drops its module `vfs` and the `seenVol` effect, memoises a host per workspace (`Map<Workspace, ShellHost>`), and one effect tracks `workspaces.active`, `commandSetOf(ws.volume.adapter)`, and `ws.volume.vol`: on a tab or set change it re-registers over `ws.vfs`, re-sets the redirect handler (`createRedirectHandler(host, ws.vfs)`), prints a banner `-- ext tab: /dev/hda is ext3 --` / `-- FAT16 tab: /dev/hda is FAT16 --`, and always re-sets the prompt from `ws.vfs.cwd`. The scrollback is shared across tabs by design. The cwd resets to `/mnt` through `VolumeStore`'s `onAdopt` (a format or load in that tab), never on a switch.

## 5. Switching

Changes on a switch: map panel, right column, Format form and summary, picker list and choice, status line, Operation bar, What changed, Ribbon, dump (position restored), selection, the lesson card (hides with its tab; the badge says it is still running; coming back shows it at the same step), `document.title`, the hash, the terminal's command set and cwd. Stays: the theme; the terminal's open/closed state, height, width, placement; the lesson window's position and minimised state; `[`/`]` apply to the active tab. Focus stays on the activated tab; on a routed Load image focus stays on the file input. *Corrected during implementation: the input the image was loaded from is hidden with its tab, so focus moves to the target tab's Load image input (`load-image-{id}`, a per-tab id beside `action-path-{id}` and `load-hint-{id}`).*

## 6. The Step strip becomes an Operation bar and a What changed panel

- **`src/components/OperationBar.svelte`** (new; replaces `StepPanel.svelte` and `Timeline.svelte`): one row under the top bar, `<section class="panel opbar" aria-labelledby="opbar-heading-{id}">` with a visually hidden `<h2 id="opbar-heading-{id}">Operation</h2>`: `Prev`, `Play`/`Pause`, `Next`, the slider (`<input type="range" class="tl-range" aria-label="Timeline step" list="opbar-ticks-{id}">` with a `<datalist>` of one option per step), then `<span class="counter">3 of 7</span> · <span class="mono op">createFile /hello.txt</span> · <span>18 blocks</span> · <span>30 events</span>` (the noun from `volume.adapter.sector`: `sector`/`sectors` on FAT, `block`/`blocks` on ext; `1 event`/`1 block` singular; a zero count omitted). Empty state: `<span class="mono">{volume.adapter.summary()}</span> · Run an action to see what it changes.` `Prev`/`Next`/`Play` and the slider keep `Timeline.svelte`'s behaviour (`goToStep`, `PLAY_MS` 700 / 1500 under reduced motion, playback stops when the tab hides). Moving the pointer over the range sets its `title` to `${step + 1} of ${n} · ${op}` for the step under the pointer, from `stepAtPointer(x: number, width: number, steps: number): number` in `src/core/timelineSlider.ts` (the nearest tick, clamped). CSS: `.opbar { display: flex; flex-wrap: wrap; align-items: center; gap: 4px 12px; padding: 5px 10px; }`, `.opbar .tl-range { flex: 1 1 160px; min-width: 120px; }`; under 760 px the summary wraps to a second line. *Corrected during implementation: the bar prints the wasm package's op names (`1 of 1 · create_file /Hello world.txt · 7 sectors · 7 events`), not `createFile`.*
- **`src/components/WhatChangedPanel.svelte`** (new; top of the right column): `<section class="panel changed"><h2>What changed</h2>`; empty state `<p class="muted">Nothing yet.</p>`.
  - **Blocks** row: `<p class="muted">{cap(noun plural)}</p>` then one button per range from `formatRanges(changedSectors(rec.changes, sectorSize))` (new pure `src/core/ranges.ts`: `formatRanges(sorted: readonly number[]): { label: string; first: number; last: number }[]`; labels `1–6`, `69`, `82–91` with an en dash). Click jumps to the range's first sector (`selection.jumpTo(first * sectorSize)`); hover and focus set `layers.hover` to the range's bytes, which the Ribbon paints as a 1 px `--focus` outline over those columns and the maps outline as cells (`outlineCell` in `core/grid.ts`, one more pass after `layers.diff`); leaving or blurring clears it.
  - **Events** grouped by the new pure `src/core/eventPhases.ts`: `groupEvents(events: readonly PhaseEvent[]): Phase[]` with `PhaseEvent = { kind: string; text: string; region: Interval | null }` and `Phase = { id: PhaseId; label: string; events: (PhaseEvent & { index: number })[] }`. A record with any journal kind (`recovery_flag_set`, `transaction_started`, `journal_block_written`, `checkpointed`, `journal_emptied`, `recovery_flag_cleared`, `recovery_scanned`, `replayed`, `transaction_discarded`, `crashed`) is grouped ext3-style, otherwise FAT-style (so ext2 records read like FAT's). FAT-style: `dir_entry_written`/`dir_entry_removed` → `directory` "Directory entry"; `fat_entry_set`/`cluster_allocated`/`cluster_freed`/`blocks_allocated`/`blocks_freed`/`bitmap_updated`/`counters_updated`/`inode_allocated`/`inode_freed`/`inode_written`/`indirect_written` → `allocation` "Allocation"; `data_written` → `data` "Data". ext3-style: every non-journal kind → `body` "Filesystem writes"; `recovery_flag_set`/`transaction_started`/`journal_block_written` → `journal` "Journal"; `checkpointed` → `checkpoint` "Checkpoint"; `journal_emptied`/`recovery_flag_cleared` → `cleanup` "Cleanup"; `recovery_scanned`/`replayed`/`transaction_discarded` → `recovery` "Recovery"; `crashed` → `crash` "Crash". Anything unknown → `other` "Other". Phases appear in order of first event. Each renders as `<details class="phase" open={openPhases.has(id)}><summary>Journal · 9 events</summary><ol>…</ol></details>`; the first phase starts open, the rest closed, and a phase's open state is remembered per phase id while stepping (component state). Each event keeps today's markup (`<code>{kind}</code> {text}`, a button when it has a region: click jumps, hover sets `layers.hover` to the region). A `Crash` phase's summary uses the `.warn` colour.
    *Corrected during implementation: `groupEvents` also maps FAT's `dir_entry_deleted` and `directory_grown` to Directory entry and any family's `raw_write` to Data. Because phases follow first appearance, a FAT16 create reads Allocation, Data, Directory entry (its first event is a FAT entry). In an ext3-style record every non-journal kind, known or not, is Filesystem writes, so Other appears only in FAT-style records.*
- The lesson card keeps "step" for its own steps; the bar's counter reads `3 of 7` without the word.
